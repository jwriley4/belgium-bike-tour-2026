Riding rhythm
Trip average, not moving average. Ardennes days run about 12 km/h once navigation stops, photos and regroups are counted; Hainaut and Flanders about 15 km/h. Moving averages are higher — 14–17 and 20–23 — but the gap is what wrecks schedules.

Why: the motor cuts out at 25 km/h, so a loaded touring e-bike will not cruise much past 24 on the flat, and every knooppunt junction costs 30–90 seconds. On a day crossing twenty nodes that is a lost half hour.

Departures: 9:00–9:30 on a normal 45–75 km day, arriving around 17:00. 8:00–8:30 on Sep 9, Sep 10 and any day with a museum in it.

Stops: sit-down lunch 60–90 minutes. Brewery and abbey stops that are the point of the day — La Chouffe, Poteaupré, In de Vrede, Café Trappisten — want 90–120. Coffee regroups 20–30. On charge days, lunch is however long the battery needs, minimum 90 minutes on a 4 A charger.
Batteries
All three bikes are 625 Wh Bosch systems — two Canyon Precede:ON 5 ST and one Cube Trapeze (corrected from an originally-quoted 500 Wh). Chargers are interchangeable across all three. The Cube still goes to the heaviest rider, which is a bike-fit call, not a battery one now — that rider will still draw a bit more power per km simply from effort, but it\u2019s no longer a structural capacity mismatch.

Assist levels: Eco adds roughly half your own power and flattens the hills; Tour adds a bit more than your own power again; Sport scales with effort and is a tool for short steep pitches; Turbo is for emergencies. Above 25 km/h none of them do anything, which is why flat Flanders days are cheap and Ardennes days are not.

Ask the rental shop for: 4 A chargers — the compact 2 A doubles every charge time. A spare battery is no longer essential now that all three bikes match, but it's still cheap insurance for Sep 5, Sep 9, and the Sep 10 brewery variant — the three days that stay genuinely tight regardless of which bike anyone's on.

Where to charge: cafés and restaurants — any 230 V socket plus your own charger. Wallonia\u2019s Bienvenue V\u00e9lo and Flanders\u2019 Fietsvriendelijk labels mark places that expect cyclists and offer charging and secure storage; filter hotel bookings by them. Car EV networks are useless — Type 2 and CCS cannot feed a bike battery.
GPX files
One file per riding day, each carrying full elevation and that day’s knooppunt numbers as waypoints — so the Garmin names the nodes as you reach them, matching the signs.

Phone: import each file into the NodeMapp app one at a time. On import NodeMapp re-snaps to its network and renumbers from the track, usually identically — glance at each day after import, especially Sep 10 where the connector meets the main leg.

Both Sep 10–11 route variants ship in the set, labelled M and B, so the route decision can wait until you are there — Sep 12 onward (Tournai → Ypres and beyond) is the same file regardless.

v12.64 — Fixed the "edits looked lost after switching browsers" scare: the main app now reads the Edits sheet live (no more minutes-long cache lag on a fresh page load, the same fix v12.62 gave the Review panel), a small banner offers a reload the moment something newer is available elsewhere — never popping up while you're mid-edit — and the Review panel now warns you, block by block, whenever a pending edit was written against text someone else has since changed, with a one-tap peek at the current live wording before you approve. Review's list is also now mobile-friendly stacked cards with real word-level highlighting of what changed, instead of a table that only worked on a wide screen. Nothing was ever actually deleted by any of this — the Sheet only ever appends — this just makes sure every device sees the same truth, promptly.
v12.63 — Two edit-box upgrades: a real Link button now opens a proper "Insert a link" popup (URL + optional link text) so links you add come out as real clickable links instead of plain text — and any bare web address you paste in auto-links itself too, no popup needed. And plain line breaks — just pressing Enter while typing — now show up as real line breaks in the app, including a blank line between paragraphs. No markdown or special typing required for either one; this isn't a switch to Markdown, just the editor now honoring the newlines you actually type.
v12.62 — The Review panel's approve/reject is now rock-solid deterministic: every submission gets a real unique server-assigned ID (a RowId) the instant it's created, and approve/reject act on that ID instead of matching rows by timestamp + identifier text. That old matching scheme could collide — the Sheet's own timestamp only tracks to the minute, and every "add a stop" submission shares the same blank identifier — so two edits landing in the same minute could be indistinguishable, which is exactly what let an approved/rejected row reappear. The Review panel also now reads the Sheet live instead of through the "publish to web" export, which had its own separate minutes-long cache lag — so what you see is always the Sheet's true current state, on every device, with nothing to wait out.
v12.61 — Places can now be deleted. Every row in the Places table gets a 🗑 button (edit mode only) that shows exactly what references it first — which day waypoints, which Table food rows, and which Beer-tab reservation card — before anything is removed, and always requires a second confirm screen even when nothing references it. A lodging place that's the real booked-night record for a day (not just a map pin) can't be deleted at all — you'll be told which day(s) and pointed to editing its details instead, or asking Jim to handle it directly. Deleting cascades: the place and every listed reference are cleared together in one action, same review-before-live pipeline as everything else.
v12.60 — The Review panel (Jim's approve/reject screen) is now a table with checkboxes instead of a stack of cards: a header checkbox selects/deselects every currently-visible row, individual rows can be unchecked one at a time, a filter box narrows a big queue down to what you're looking for, and Approve/Reject act on the whole selection in one click instead of one row at a time. Built for the volume the new drag-reorder can generate — dozens of rows resolve deterministically: each is only marked done once the server actually confirms it (or confirms it's already resolved elsewhere), and a genuine failure stays visibly flagged and pending rather than silently vanishing or reappearing later.
v12.59 — The Places table's # column is now much faster to reorder: grab the ⠿ handle and drag a row to where it belongs (drop above or below another row), or just type the target number directly into the box and tab away — either way every affected place's # updates automatically, no more clicking one step at a time. Safe to use freely: # is purely the table's registration order and never affects a place's actual day/map assignment.
v12.58 — The Places table is now directly editable in Edit mode: use the ▲/▼ buttons next to the # column (when sorted by #) to reorder a place's registration number, and the new ✏️ next to a place's Day cell opens an "Edit days" screen — move a place to a different day, remove a day reference, or add it to a new day, each with a confirm-before-applying safeguard (lodging places get an extra warning, since this only moves the map pin, not the actual booked-night record).
